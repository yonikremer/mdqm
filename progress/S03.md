## Summary
Stage D4 turns an OpenAPI document into the semantic layer's table skeletons for that API source.

- `src/mdqm/pipeline/stages/openapi.py` — `OpenApiStage` (the S01 `Stage` shape: `name`,
  `inputs_hash`, `run`, a `sources` property for `--source`), one `generated/openapi_<source>.yaml`
  per source through `ctx.write_generated`, so `generated/` is the only write path.
- Per `GET` collection it writes a `tables.<source>.<collection>` entry: **columns** from the item
  schema (native type text kept, portable `NormalizedType`, ordinal in document order), **indexes**
  from the declared query parameters (the planner's "filterable column"), and **provenance** with
  the paging style, the page-size parameter, the envelope key the rows come from and the
  next-page token.
- Per source it writes `sources.<name>`: `adapter: openapi`, the spec path, the auth header with its
  secret *reference*, and the rate-limit headers the document itself promises (`X-RateLimit-*`,
  `Retry-After`).
- The parsing is A06's, not a second reader: it calls `read_endpoints`/`read_spec` from
  `mdqm.adapters.openapi`, so the skeleton cannot disagree with what the adapter executes (a test
  asserts the two agree on names, normalised types and indexes).
- Every operation that is not a table — a write, a lookup behind a path parameter, a single-object
  answer, an array of opaque objects — is listed in `StageReport.skipped` with the reader's reason
  ("a POST operation: only GET is ever exposed", "it takes a path parameter: one resource, not a
  collection", …).
- The payload is validated as a `SemanticLayer` *before* it is buffered, so a skeleton that would
  make the layer unloadable fails as a stage failure instead of as tomorrow's broken semantic layer.
- Identity key, mutability, time columns and default window are deliberately not written: a spec
  knows none of them, and "unknown" is already the layer's conservative default (D5/D6 measure them).

## Decisions
- **Promoted four private records in `adapters/openapi.py` instead of importing privates**:
  `_Column`/`_Param`/`_Paging`/`_Endpoint` -> `SpecColumn`/`SpecParam`/`SpecPaging`/`SpecEndpoint`,
  and `_endpoints`/`_read_spec` -> `read_endpoints`/`read_spec` (all in `__all__`). This is the
  smallest promotion that lets the stage reuse the parser: the alternative was a second spec reader
  (forbidden by the task) or importing underscore names across modules. `read_endpoints` now returns
  `SkippedOperation(label, reason)` instead of bare labels; `OpenApiAdapter.ignored_operations`
  still returns the labels in the same order, and the new `skipped_operations` carries the reasons.
  The only edit outside the task's `owns` this needed in A06's own test file: one import line and
  one call in `tests/unit/test_openapi_adapter.py` (`_endpoints` -> `read_endpoints`); A06's suite
  is green unchanged otherwise.
- **`TableSemantics` gained two optional fields, `columns` and `indexes`** (`semantic/models.py`,
  reusing `mdqm.models.catalog.Column`/`Index`). The layer had nowhere to put a skeleton's columns,
  and the section has to load back through `load()`: `generated/` is validated as one
  `SemanticLayer` with `extra="forbid"`, so an out-of-schema section (like `capabilities.yaml` or
  `profile_<source>.yaml`, which live in a store-side root) would have made the whole layer
  unloadable. Reusing the catalog models rather than defining a second column type keeps a skeleton
  and a probe from disagreeing about what a column is. Additive and defaulted, so no existing YAML
  changed meaning.
- **Pagination, envelope and rate-limit facts live in `provenance.evidence`.** The layer has no
  paging field because a database table has none; inventing an API-only block would have made the
  schema less uniform than the facts warrant. They are one short sentence each, so the API compiler
  and a human debugging a page loop both read them.
- **Rate-limit headers are read from the document's declared response headers, not from a live
  answer.** D4 must stay deterministic and cheap (no source call, no clock): the document already
  states `X-RateLimit-Limit`/`-Remaining`/`-Reset` and `Retry-After` (the mock API decorates every
  protected operation). Seeing a header in a real response is a probe/runtime concern.
- **`inputs_hash` includes the documents themselves**, not the spec path: a spec whose content
  changed but whose path did not must rebuild the skeleton. `ctx.exec_ts` is not in the hash — a
  skeleton is not a fact about a day, so a nightly re-run must skip and leave the diff empty.
- **The payload is validated as a `SemanticLayer` before the buffer**, and a failure is a stage
  `ValueError` (so the runner records `FAILED` and writes nothing). Cheap, and it makes the "one
  unknown key kills the whole layer" failure impossible to ship.
- **`read_specs(configs)`** is the deployed entry point: it reads every `openapi` source's document
  from the path its config names, through the adapter's own YAML-or-JSON reader.

## Deviations
- The stage is not registered in `PipelineContext`'s `available_stages()` (`pipeline/core.py`, owned
  by S01 and outside this task's `owns`): the object is complete and tested, and wiring it is a
  one-line addition in whoever owns the stage registry next. Same reason `mdqm bootstrap run` does
  not list D4 yet.
- `docs/DESIGN.md` section 10's D4 row ("GET endpoints, filter params, pagination, auth, rate-limit
  headers; generates an adapter") is satisfied for everything except *generating an adapter*: the
  adapter already exists (A06) and the skeleton names the source with `adapter: openapi`, so no code
  generation was invented here. Nothing else in DESIGN changed; the `columns`/`indexes` extension to
  `tables` is recorded above instead of editing `docs/DESIGN.md` section 12, which this task does
  not own.

## Plan issues
- `generated/` mixes two kinds of section: sections that are part of the semantic layer
  (`capabilities.yaml` and `profile_<source>.yaml` are not) and sections that are. Loading a root
  that holds a `profile_<source>` or `capabilities` section *fails* today, because `load()` validates
  everything in `generated/` as one `SemanticLayer` with `extra="forbid"`. That is not S03's to
  change (S01 owns the context and C04 the loader), but the backlog needs a decision: either those
  facts move to a store-side root, or the loader grows a declared per-section model registry.
- `TASKS.md`'s S03 acceptance names the golden YAML and the `skipped` reasons but not the "loads
  back through the semantic loader" requirement that this run's instructions added; the loader
  compatibility is what forced the `columns`/`indexes` model change above, so the two should be
  stated together in the task text.
