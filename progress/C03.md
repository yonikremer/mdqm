## Decisions
  - Month-end rule: clamp to the last day of the target month (`2026-01-31 + 1mo = 2026-02-28`),
    documented in `test_add_to_is_calendar_aware`. Adding 28 days would change the window; rolling
    into March would skip February. Same rule on the way back (`subtract_from`).
  - "Locale-free, never guess": compact durations must be lowercase ASCII digits and one component;
    `1D`, `1M`, `1min`, `1.5d`, `1 d`, `1d12h`, `-1d` and Arabic-Indic digits are rejected with a
    message that names the valid forms. Multi-component spans are ISO-only.
  - Naive instants (and date-only text) in `time.*` mean **UTC**; aware values are converted. The
    canonical example uses a naive `since`, and mdqm is UTC internally, so assuming a local zone
    would silently move the window.
  - `limit` is a strict int (`"10"` is refused instead of coerced): a quoted number is a bug in the
    caller, and saying so is cheaper than guessing.
  - Filter `value` is deliberately untyped (`Any` + one operator-aware validator) so the agent gets
    one message at `filters.0.value` instead of a union's per-branch "expected X" noise. The JSON
    Schema still declares `["string","number","boolean","array"]` for it.
  - `order_by.by` must be a selected alias, a measure/column name or a group_by key: a typo there is
    otherwise a silent sort by nothing.
  - `spec_schema` accepts either a `SemanticVocabulary` or the loaded semantic layer *mapping*
    (`vocabulary_from_semantic` reads `tables`/`measures`/`approved_joins` keys). C04's
    `SemanticLayer` is not written yet, so the mapping form keeps this task unblocked; wiring a
    `SemanticLayer` in later is `spec_schema(layer.model_dump())`.
  - Structured-output portability: keywords outside a conservative allowlist are stripped
    (`minLength`, `default`, `format`), every object gets `additionalProperties: false`, and the
    tests assert no `$ref` cycle, no dangling `$ref`, and no keyword outside the allowlist.
  - Aliases are supported on measures only; a plain selected column keeps its own name.
## Deviations
  - `examples/query_specs.json` is unchanged. It is in the `owns` list, but task C09 compiles every
    `valid` example to committed golden SQL: adding examples here would silently expand C09's
    contract. The tests load and validate every existing entry instead, which is the acceptance item.
  - Two-stage validation: structural (pydantic) issues are reported first, and cross-field checks
    run only once the JSON shape is valid. So a spec with both a structural mistake and a grouping
    mistake needs two round trips. The alternative (reporting cross-field issues about fields that
    did not validate) would produce misleading paths.
  - OpenAI `strict: true` additionally requires every property to be `required` and optionals to be
    `["<type>", "null"]`. `spec_schema` is a valid, closed, cycle-free schema (the acceptance
    criterion) but does not rewrite `required`; that transformation was not asked for and would make
    every optional field mandatory for the agent.
