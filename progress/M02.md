## Summary
`find_data` is now a real tool instead of the stub in the tools package front door. It takes a free-text question
(Hebrew or English) and answers with H05's Context Pack (unchanged ranking, plus `omitted` with `reason`), a spec
skeleton built from the best matched measure, a short `hint` when nothing matched, the refs it dropped for a source
scope, and `tokens_total`. A question that matches nothing returns an empty pack and a hint, not an error, and is
appended to H04's `empty_searches` log with the caller's id. Two refusals are `ErrorResponse` values and are audited:
a question with no word in it, and a `sources` entry this deployment does not declare (the fix lists the valid ones).
The whole answer — pack plus skeleton — is kept inside the pack budget: the pack is rebuilt with the skeleton's cost
subtracted, and if the skeleton still does not fit it is dropped and `hint` says why.
The tool is proved over a real in-process MCP roundtrip on loopback (`mcp` 2.3.0, `create_server`, bearer tokens), so
the identity the handler sees is the caller's, and in both languages for the same question.
## Decisions
- **The Context Pack is wrapped, never re-ranked.** Relevance, the caps and the budget cut stay H05's; this module only
  reads `pack.items`/`pack.omitted` and never touches a score. A second ranking would disagree with the pack the
  client hook injects for the same prompt.
- **The skeleton invents nothing.** It carries `from` (the match's first source table, sorted so it is stable),
  `select` (the matched select column when one exists, then `{"measure": ...}`) and `group_by` (the matched categorical
  column on that table). It deliberately carries **no `time` window and no `agg`**: either silently changes what the
  answer means, and the linter's own `PARTITION_SCAN_ALL` / spec error carries the exact fix when one is needed. A test
  proves the skeleton validates through `parse_spec`.
- **No spec body exists for an approved example yet.** `ApprovedExample` (H04) holds a name, a question and a ref, so
  when no measure matched but an example did, the skeleton names the example (`based_on="example:<name>"`) and says to
  adapt it rather than inventing a spec from a name.
- **`sources` is a real scope, and its narrowing is visible.** H05's pack has no source scope, and the index holds every
  source, so a scoped call scopes the layer (measures keep only the in-scope conversions, joins need both ends in scope)
  and then drops the table lines of other sources, returning them in `excluded`. With `sources` omitted none of that
  code runs: a test asserts the answer is byte-identical to `build_pack`'s own output.
- **The re-render for that drop is mirrored, and guarded.** Dropping a line has to rebuild the pack's text, and H05
  keeps its renderer private. `_render_items` mirrors that one layout and a test re-renders a real pack through it and
  asserts equality with H05's own `text`, so a layout change in H05 fails here instead of drifting.
- **`limit` is gone; `sources` took its place.** The old stub's `limit` ("how many matches") has no meaning for a
  budgeted pack that already caps itself (`MAX_TABLES`, `MAX_EXAMPLES`, the token ceiling). One knob fewer for a weak
  model, and it changed the wire schema, so `docs/tool-schemas.json` was regenerated (never hand-edited).
- **The dictionary slot is its own, not a field on `misc.ToolServices`.** `misc.py` belongs to M05/M06 and both were
  being edited in parallel; a second module-level slot (`configure_find_data` / `use_find_data` / `reset_find_data`,
  the M05 pattern) keeps this task inside its own files. A later wiring task can merge the two slots.
- **Empty-search logging goes through H04's public `search`.** H05 searches one word at a time with `log_empty=False`
  (a row per word would be noise), so `find_data` searches the whole question once, only when the pack came back empty.
- **Punctuation-only input is refused, a stopword-only question is not.** `"   ...   "` is a caller bug (nothing to
  search); `"how much"` is a question the layer cannot answer, so it gets the empty pack and the hint.
