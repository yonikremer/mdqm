## Summary

Stage D9 as code: `src/mdqm/sql/fingerprint.py` (pure, no I/O) parses one statement in its own
sqlglot dialect and reports base tables, join edges with the conversion on one side, filter columns,
time columns, GROUP BY terms, aggregates, rounding/scale expressions and typed `ConversionHint`s;
it also normalises (literals and clock reads marked, aliases renamed to `t1..tN`) and hashes that
into a sha256 fingerprint. `src/mdqm/pipeline/stages/mining.py` merges statements that share a
fingerprint (calls, statements, distinct users, first/last seen), ranks them with
`a*log(count) + b*0.5**(age/half_life) + c*distinct_users` (`MiningWeights`), upserts them into
SQLite with a per-source watermark, and exposes the conversion hints with their evidence. Migration
`0005_mining.sql` adds `mined_query`, `mined_ingest` and `mining_watermark`.

## Decisions

1. **Idempotence by input hash, not by statement.** A batch is identified by
   `batch_digest()` (sha256 over dialect + text hash + calls + user + last_seen, order-independent).
   A batch already in `mined_ingest` writes nothing and reports `skipped`; its counters are additive
   per *new* batch. This is DESIGN section 10's rule ("unchanged input => skip"), and it is the only
   rule that survives a source that re-delivers a window. A cumulative-counter source
   (`pg_stat_statements` totals since reset) must be pulled as deltas by its adapter; adding
   overlapping totals would count one execution twice. Documented in the module docstring.
2. **The watermark is what was *seen*, not what could be parsed.** A statement we cannot parse still
   came from the source, so the watermark advances past it and the next pull does not re-report the
   same failure forever. It never moves backwards (an out-of-order pull cannot rewind it).
3. **A join key is not a filter.** Columns that take part in an equality classified as a join edge are
   removed from `filters` (or-17: a comma join with `WHERE a = b` has no filters), and a column inside
   an aggregate (`HAVING SUM(credit_limit) > 100000`) is filtered as a sum, not as a column.
4. **Time columns are a name heuristic plus evidence.** Mining has no catalog: a filter column is a
   time column when its name ends `_time`/`_at`/`_ts`/`_date` **and** a range predicate bounds it.
   `deleted_at IS NULL` is a flag test, not a window. A later stage with catalog types (D1/D5) can
   refine this; there is no place in this task to ask for types.
5. **Now-like functions are read from the statement's tokens**, not from the AST: sqlglot folds
   `now()`, `SYSDATE` and `GETDATE()` into one node, so the AST cannot tell them apart, and
   `now_functions` must report the name that was written.
6. **Rounding/scale expressions are reported as rendered by sqlglot**, not as byte-copied source text.
   `x::varchar` and `CAST(x AS VARCHAR)` are the same conversion; the corpus comparison (and the
   corpus's own consistency check) already normalises case and whitespace, so the test compares the
   parsed form instead of a byte slice.
7. **GROUP BY keeps the qualifier as written** (`c.status`) because that is what the statement says;
   the corpus is inconsistent here (or-13 writes `"C"."STATUS"` and expects `status`), so the test
   compares a group-by term on its column/expression, not on the alias it was written through.
8. **Aliases are canonicalised** (`t1`, `t2`, ... in appearance order), so renaming an alias does not
   change a fingerprint. CTE names are kept: a CTE reference is labelled by the CTE's name (the
   analyst reads `recent`, not the alias `r`), and a CTE/subquery is not a base table.
9. **Per-user identity, not a user count.** `users` is stored as a sorted JSON array of identities
   (bounded by the ~100 users of the target organisation), so merging two batches is a set union
   rather than an unrecoverable sum of counts.
10. **Unknown age earns no recency credit** (`age=None`), because "we do not know when this ran" must
    not look like "it just ran". `age=0` is a real, maximally fresh value.
11. **Migration is `0005_mining.sql`**, renumbered twice on rebase as other lanes landed
    `0003_history.sql` (H03) then `0004_context_index.sql` (H04). Renumber mine and only mine.
12. **One marker per stripped shape**: `{lit}`, `{now}`, `{interval}`. An interval's unit is kept
    (`TRUNC(x, 'MONTH')`), because the granularity is a different query.

## Not verified

- **No live source was queried.** No container runtime is available on this machine, so
  `pg_stat_statements`, Oracle `V$SQL` and T-SQL Query Store were not read: the stage is verified
  against the structured fixtures in `tests/data/queries/*.sql` and against `RawQuery` values, which
  is exactly the shape those adapters will hand over. The adapter side (`mine_queries(since)`) already
  exists in `adapters/base.py`; wiring a real source to `ingest()` and confirming the dialect/counter
  columns is still to be done (phase-MVP item, DESIGN section 11).
- **Concurrency**: `ingest()` writes in one `store.writing()` transaction and inherits H01's
  single-writer rule, but two processes mining two sources at the same instant were not exercised
  here (SQLite busy timeout applies).
- **Watermark continuity across sources** is per source only; the MCP's own history source
  (cross-source joins) is not wired yet, because no history table exists (H03).
