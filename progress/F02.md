## Summary
Added the shared frozen domain models in `mdqm.models` (12 modules): `Capability`/`Capabilities` (tri-state
capabilities per source), `CatalogSnapshot` + `Column`/`Index`/`ForeignKey`/`Table` with native and
normalised types, `Partitioning`/`PartitionBound`, `TableStats`, `RawQuery`, `PlanSummary`, `Limits`,
`Fragment` and `ErrorResponse`. `snapshot_hash()` gives an order-independent content hash for schema drift;
`mdqm.models.schema.export_json_schemas()` writes one deterministic JSON Schema file per public model (15).
All models are frozen with `extra="forbid"`, timestamps are aware and stored in UTC, and every model
round-trips through JSON (`model_validate_json(model_dump_json()) == model`), enforced by a
`Annotated[..., AfterValidator]` guard on the model's JSON-carrying dicts. `tests/unit/test_models.py` covers
the invariants table-driven over every public model, plus the validation each model owes its callers, a
hypothesis property test for hash order-independence, and the DESIGN error shape.

## Decisions
- **Tri-state capability is `supported: bool | None`** (`None` = unknown), not a 3-value string enum, so the
  JSON is `true|false|null` exactly as the task writes it; `Capability.state` renders
  `supported|unsupported|unknown` for reports, and `Capability.source` is `probed|override`.
- **`Capabilities.capabilities` is a dict keyed by capability name** with `get/supports/is_unknown/
  unsupported()/unknown()`. A capability nobody probed reads as *unknown*, never as failure: the caller takes
  the declared fallback.
- **`Table.schema_name`, not `schema`** (avoids shadowing pydantic's schema machinery); `qualified_name`
  renders `schema.name`.
- **Closed vocabularies with an `OTHER` catch-all** (`NormalizedType`, `TableKind`): generic across engines
  while still checkable; ES index families and REST endpoints are `TableKind.INDEX`/`ENDPOINT`.
- **`snapshot_hash` excludes `captured_at`, `row_estimate` and column `ordinal`** and sorts tables, columns,
  indexes and foreign keys by their canonical JSON. Reason: `captured_at` would make every run differ, and
  row estimates/ordinals are statistics churn, not structure (they live in `TableStats`). `source` *is*
  included so a drift report can name the source.
- **Range bounds are UTC datetimes in `PartitionBound`** (adapters parse the engine's text form once); list
  partitions use `values`, and `Partitioning.partitions_total` is `len(bounds)` or `None` when the probe
  could not enumerate.
- **`Limits` has no defaults.** Timeout/row/byte/partition caps are the organisation's numbers and come from
  config (F03); the core invents none.
- **`Fragment` carries exactly one of `sql`/`dsl`/`request`** (validated), with `params` documented as JSON
  scalars and JSON-native enforcement so the round-trip invariant cannot be broken silently.
- **`PlanSummary.raw` is a string** (plan text, JSON plan included): comparable, hashable and round-trippable
  across PostgreSQL/Oracle/SQL Server/ES.
- **`ErrorResponse` dumps with `exclude_none=True` by default** so the agent sees exactly the DESIGN shape —
  no `null` noise, optional `valid_values`/`did_you_mean` only when set; `status` is `Literal["error"]`.
- **Schema files are snake_case, sorted-key JSON with a trailing newline** (`catalog_snapshot.json`, ...): the
  bytes depend only on the models, so regeneration produces a real diff or none.
- Extra fields the task did not name, each because a dependent task reads them: `RawQuery.mean_time_ms` (A04),
  `PlanSummary.indexes_used` (the response shows `plan {partitions_scanned, index}`), `TableStats.checksum`
  (DESIGN's mutability fallback when counters are unreadable), `Table.kind`/`primary_key`, `Index.index_type`/
  `predicate`.
