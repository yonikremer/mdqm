## Summary

`src/mdqm/testing/loaders/elastic.py` installs a composable index template for
`mdqm-usage-events-*` (explicit mapping, `dynamic: strict`), creates the monthly indices
`mdqm-usage-events-YYYY-MM` spanning the world's 8 data months plus the empty months (12 in
total, ending at the world anchor month `2026-01`), points the alias `mdqm-usage-events` at all of
them with the newest index as the only write index, and bulk-loads `usage_events` with `_bulk`
NDJSON over plain `httpx`. The event month of `start_time` decides the index; `insertion_time` is
stored as a date field, so a late-arriving row lands in its event month while its ingestion time
points at a later month. The module also defines `EsSearchView`: the adapter's object, whose only
operation is `POST /{alias}/_search`.

## Decisions

- **Index and alias names** follow `scripts/seed_oss.py` and the prompt: `mdqm-usage-events-YYYY-MM`
  indices, alias `mdqm-usage-events`, template `mdqm-usage-events`. See Deviations for TASKS.md's
  shorter spelling.
- **Idempotency: delete-and-reload *and* stable `_id`s.** Every run deletes all
  `mdqm-usage-events-*` indices, recreates the months and re-bulks. The document `_id` is
  `str(event_id)`, so a crash between delete and load (or a manual re-send of one batch) overwrites
  instead of duplicating. The delete is what makes a *shrunk* world shrink; the id is what makes a
  crash safe. Both are documented in the module docstring.
- **12 months, not 8.** The span is the union of the months that carry rows and a contiguous
  12-month span ending at `WorldConfig.anchor`'s month, so a month-ahead query hits an existing
  empty index instead of a 404, and a world with a longer window can never lose a document. The
  newest index (the anchor month) is the write index.
- **Layout is `-YYYY-MM` (hyphen)**, matching `seed_oss.py`: ES accepts dots too, but one spelling
  across the two seeds beats two.
- **`as_utc` on every timestamp.** A naive datetime is taken as UTC instead of the machine's local
  zone; otherwise the same world would land in different months on a laptop in Jerusalem and a
  server in UTC. This was caught by a unit test.
- **`EsSearchView` instead of an `EsAdmin`.** The adapter is handed an object with exactly one
  operation (`search` -> `POST /{alias}/_search`); there is no method it could call to write.
  `MDQM_ES_ADMIN_USER`/`_PASSWORD` and `MDQM_ES_SEARCH_USER`/`_PASSWORD` are separate fields, and a
  unit test asserts the view sends the search credential and never the admin one.
- **`track_total_hits: true` in the search-only test.** Without it ES caps `hits.total` at 10000,
  which silently satisfied a wrong assertion with a 50k world until it was fixed.
- **Template settings** are 1 shard / 0 replicas: a single-node dev cluster would only ever report
  an unassigned replica, i.e. yellow, for no benefit.

## Deviations

- TASKS.md D07 spells the layout `usage-events-YYYY.MM` behind alias `usage-events`. This
  implementation uses the prompt's and `seed_oss.py`'s `mdqm-usage-events-YYYY-MM` /
  `mdqm-usage-events`. Same design, one name; the `mdqm-` prefix also keeps the dev cluster's
  indices namespaced.
- New file `tests/unit/test_loader_elastic.py` is outside D07's `owns` list. The acceptance
  requires Docker-free determinism tests and the only sensible home is `tests/unit`; nothing else's
  file was edited except `loaders/__init__.py.__all__` (the loader registry line, one word).
- `docs/dev-env.md` was not touched: it already documents the `es` service and its port. The CLI is
  documented in the module docstring instead.

## Dependencies

None. `httpx` is already a base dependency and is used instead of the `elasticsearch` package,
whose client is strictly coupled to one server version (the loader must work against 8.x and 9.x).
No `elasticsearch`-specific plugin or extension is installed or enabled.

## Not verified

- **Credential-level read-only enforcement.** The dev compose service runs with
  `xpack.security.enabled=false`, so there is no account to test and no way to prove that a
  `read`-only role is rejected. What is proven live: the adapter is handed an object whose only
  operation is `_search`, and the loader uses a separate credential field. On a secured cluster the
  adapter's role must be `read` + `view_index_metadata` on `mdqm-usage-events` only; that wiring
  belongs to the Elasticsearch adapter task, not D07.
- **Elasticsearch 9.x.** Only 8.15.3 was available in this environment. The code uses no versioned
  API beyond `_index_template`, `_bulk`, `_count`, `_search`, `_alias` and `_cat/indices`, all of
  which exist in both.
- **Non-ASCII data through `_bulk`.** The world's customer *names* are Hebrew but `usage_events`
  carries only ids and numbers, so no Hebrew string is exercised end to end here. `ensure_ascii`
  is off and the body is sent as UTF-8 bytes, so this is a test-coverage gap, not a code gap.

## Plan issues

- The D07 acceptance criterion "a date-range query on a single month touches one index via index
  pattern" is subtly wrong for a wildcard pattern: Elasticsearch expands `mdqm-usage-events-*` to
  all 12 indices *before* it sees the range, so `_shards.total` is 12 even though the returned rows
  are the single month's (proven above). One index is touched only when the month index is named
  explicitly (`_shards.total == 1`). Both cases are asserted; the criterion as worded can never
  hold for a wildcard.
- D07's `owns` list has no unit-test file although the prompt (and any honest determinism claim)
  needs one; add it to the task definition.
