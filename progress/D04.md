## Summary

`src/mdqm/testing/mock_api.py` is a FastAPI app that behaves like an internal API with an OpenAPI
spec, so the OpenAPI adapter and its tests have something real to talk to:

- `GET /rates` (filters `currency`, `date_from`, `date_to`; `limit` + opaque `cursor` paging with
  `next_cursor` and `total`), `GET /customers/{customer_id}/score`, `GET /slow?delay_ms=`
  (capped, for client-timeout tests), `GET /health`, and `GET /_stats` (per-endpoint call counts,
  so a test can prove cache/coalescing removed source calls rather than just got faster).
- `X-API-Key` auth (constant-time compare, never echoed), `X-RateLimit-Limit/-Remaining/-Reset` on
  every protected answer, `429` with `Retry-After` when a key's budget is spent (budget and window
  configurable), and one error envelope (`{"error": {"code", "message", "details"}}`) for every
  non-2xx answer, including parameter errors (`400`, not FastAPI's `422`).
- The spec the app serves carries the `apiKey` security scheme, the filter/paging parameters and the
  `429` + `Retry-After` documentation — exactly what the design's D4 stage reads.
- `tests/data/specs/fx.yaml` is the checked-in copy, generated by
  `python -m mdqm.testing.mock_api --write-spec tests/data/specs/fx.yaml`; the drift test compares
  it byte for byte with the live spec and tells you that command when it fails.
- `tests/unit/test_mock_api.py` drives it in process (`httpx.ASGITransport`), and one test runs the
  same app on a real ephemeral loopback port and shows the teardown closes it.

## Decisions

1. **In process first, port second.** The brief and `pytest-socket` require the socket-free path, so
   `MockApi.client()` (ASGI transport) is how the tests talk to it and `MockApi.serve()` (uvicorn in a
   thread, `127.0.0.1`, port 0) exists for the acceptance item "starts on an ephemeral port and tears
   it down" and for a container. Both are covered by tests; nothing in the module needs a socket.
2. **`pytest-socket` needs loopback in this module, not because of the mock.** On Windows, CPython
   builds the asyncio event loop from a *loopback socket pair* that also **connects** to 127.0.0.1, so
   an empty allow-list breaks loop creation (the loop then dies in `__del__` and every async test
   errors at setup). The module therefore opts in with `pytest.mark.enable_socket` plus an autouse
   fixture that allows `127.0.0.1` only, and `test_the_module_cannot_reach_the_internet` proves a
   non-loopback connection is refused — so "no internet" is asserted, not assumed.
3. **Fixed window, not a token bucket.** The point is the response shape (`429` + a whole number of
   seconds in `Retry-After`), which is what `mdqm.ratelimit.parse_retry_after` consumes. Time is
   injected (`clock=`), so the window is crossed without sleeping.
4. **The API key has no default and an empty key authenticates nothing.** A mock someone forgot to
   configure fails closed instead of answering. The container entry point reads
   `MDQM_MOCK_API_KEY`; tests pass a throwaway literal. No key value lives in `src`.
5. **Public paths are exempt from both auth and the budget**: `/health`, `/openapi.json`, `/docs`,
   `/redoc`, `/_stats`. A liveness probe must not spend a data budget, and a counter must not change
   what it measures (tested: `/_stats` twice reports the same numbers).
6. **Stats count handled requests only.** The guard increments `unauthorized`/`rate_limited`, the
   handlers increment `calls`, so a refused request never looks like a source call.
7. **The spec is decorated once, in `_MockFastAPI.openapi()`**: shared error responses, the
   rate-limit headers and the removal of the auto-generated `422` live in one idempotent function, so
   endpoints cannot drift apart. The two orphaned validation schemas are dropped with it.
8. **`_Budget` is tested directly** (table-driven) besides through HTTP: it is the pure core of the
   429 semantics, including the "exactly at the window boundary" case.

## Deviations

- The task text says "uvicorn in a thread" for the pytest fixture; the fixture that most tests use is
  the ASGI transport instead, and the uvicorn-thread path is the `mock_api_served` fixture used by the
  port test. Same app, same behaviour; this is what `tests/unit`'s socket block requires.
- The task text names one `mock_api` fixture. Here `mock_api` is the service object (counters, budgets,
  spec), `mock_client` is the socket-free client, and `mock_api_served` is the ephemeral-port fixture.
  Consumers (the OpenAPI adapter tests) should use `MockApi` + `MockApi.client()` directly; fixtures in
  a test module are not importable across modules, and a shared conftest is not mine to edit.
- `uvicorn` is now declared in the `dev` extra: the real-port fixture and the container entry point
  need it, and it was only present transitively through `mcp`.

   the `api` profile; `docker-compose.yml` belongs to D01 and was absent. Whoever lands D01 should add
   a `mock-api` service on profile `api` running `python -m mdqm.testing.mock_api --serve` with

2. **The task text predates the socket reality of `tests/unit`.** It prescribes "uvicorn in a thread"
   and a single ephemeral-port fixture; on Windows an async unit test cannot even create an event loop
   under a fully blocked socket, so every async mock-API test needs the `enable_socket` opt-in plus a
   `127.0.0.1`-only allow-list. Worth a line in the shared test notes (C13 already flags the same
   Windows quirk).
3. `examples/` has no `openapi` source example, so the config shape the adapter should expect (base
   URL, auth header secret, rate limit) is still only in `docs/DESIGN.md` prose. The mock matches that
   prose (`X-API-Key` from a secret reference, GET only, rate-limit headers) but I deliberately did not
   invent a YAML example outside this task's files.
