## Summary
Candidate pairs are same-table, categorical X, co-used columns first, and capped. Cramér's V, mutual information, and per-category NULL/zero/blank rates (plus mean and nearest-rank quantiles for a numeric Y) are pure functions of the sample. A filter value that a complete distribution does not contain is `VALUE_NOT_IN_DATA` before execution, with the closest real values and their frequencies. Case, whitespace, Hebrew points, a consonantal transliteration, and the value map's synonyms count as the same value. A sample, a non-empty tail, or an unprofiled partition is verified with a bounded lookup first; if that lookup cannot run, the filter is not rejected.
## Decisions
- Latin typos are not collapsed by stripping vowels. The consonant skeleton is used only across the Hebrew/Latin boundary, so `activ` is not treated as `active`, while `שלום` matches `shalom`.
- Suggestions that are within edit distance 2 are returned; unrelated frequent values are not padded in beside a real near miss.
- The linter rule calls the gate with no probe, so a stale column stays silent there. The query tool runs the probe before compile.
## Deviations
The hard error is `VALUE_NOT_IN_DATA`, a new code next to `UNKNOWN_VALUE`, so a dictionary miss and a value the column never holds stay distinct. Both are refusals.
