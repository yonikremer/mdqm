## Summary          Multi-stage `Dockerfile`: `python:3.12-slim-bookworm` builder that installs `.[pg]` from a
                     staged `/wheelhouse` with `--no-index --only-binary=:all:` into `/opt/venv`, then a slim
                     runtime stage that copies only the venv (no compiler, no pip, no wheels), runs as
                     `10001:10001`, declares `/data` + `/cache` volumes, reads secrets from `/run/secrets`,
                     `HEALTHCHECK`s `GET /healthz` with the image's own python, and `ENTRYPOINT ["mdqm","serve"]`
                     with host/port from `MDQM_SERVER__*`. `.dockerignore` keeps `.venv`, `.worktrees`, `.git`,
                     caches, `data/`, `*.duckdb`/`*.sqlite`, `tests/`, dev tokens out and keeps `wheelhouse/` in.
                     `scripts/check_offline_install.py` is the runnable offline-install proof: pure-Python
                     allowlist/recipe checks (pinned base image, `HEALTHCHECK`, non-root `USER`, no literal
                     credential, no `pip install` in the runtime stage; requirements read from `pyproject.toml`,
                     not from stale installed metadata), then the wheelhouse build, a fresh-venv offline install,
                     and a smoke test that includes a real migration run. `docs/deployment.md` documents the
                     air-gapped build (wheelhouse, base-image tarball, hatchling, platform-specific wheels), the
                     volumes, uid/permission requirement on mounted secret files, and what must never download.
## Decisions        - The builder always installs from `wheelhouse/` in the build context (no conditional `COPY`,
                     which Docker cannot express). The documented build is therefore two commands: stage the
                     wheelhouse, then `docker build`. This is the air-gapped target's real shape, and it makes
                     the image's dependency set exactly the staged, reviewable artefacts.
                   - `--only-binary=:all:` is stricter than the task's "fail on an sdist needing a compiler":
                     principle 8 says the mirror carries wheels only, so any sdist fails the check.
                   - `oracle`/`mssql` are deliberately not installed: their driver verdicts are open tasks. Only
                     `pg` ships, per task text.
                   - Host defaults to `0.0.0.0` and port to `8765` in the image (a container must bind off
                     loopback to be reachable); the laptop default in `mdqm.config.settings` stays `127.0.0.1`.
                   - Secret slots are detected by name suffix, which makes `MONKEY=1` a false positive. Safe side
                     for a leak check; noted in the docstring and covered by a test.
                   - `wheelhouse/` is the default stage directory and is already in `.gitignore`.
