## Summary          Seeded, OS-independent generator of one synthetic organisation in three storage forms plus ground truth
(`src/mdqm/testing/world.py`). `build_world(WorldConfig)` returns frozen dataclass rows for `crm.customers`,
`billing.accounts`, `billing.usage_events`, `billing.accounts_hist`, `erp.customers` and `World.expected`, the ground truth.
Truth is computed first and the three storage forms are derived from it, so `expected` is truth by construction, never a
recomputation of the code under test. Determinism: one `random.Random(seed)` consumed in a fixed order, no clock
(`anchor` is the constant 2026-01-01T00:00Z), integer money arithmetic, `render_json` sorts keys and writes LF/UTF-8, and
`world_hash` is the SHA-256 of those bytes. ~50k usage events over 8 monthly partitions; `accounts_hist` is
mutable_critical with several strictly increasing revisions per account. CLI: `python -m mdqm.testing.world --seed N
--out PATH [--small] [--customers/--months/--events-per-customer/--max-lag-seconds/--lag-violations]`.

## Decisions
1. **Half-up lives in one function** (`round_half_up`, integer arithmetic). `round_half_even` exists only so the ground truth
   can record what the wrong rule would give (2500 -> 0, 12500 -> 10000); it never builds stored data.
2. **One planted quirk per customer.** Boundary customers, NULL-limit customers, erp exceptions and duplicates are dealt
   without replacement, so every fact has exactly one cause and the ground-truth lists are exact.
3. **Backdated corrections keep event_id unique.** A correction is an *appended* row with a new `event_id` that points back
   through `corrects_event_id`, and its insertion_time is 3-6h after the original event (inside `max_lag`, so the lag
   invariant still holds). Ground truth lists before/after units. Decision: an append-only table must not rewrite or
   duplicate the primary key, and a duplicate `event_id` would break D03's primary key.
4. **Scale knobs are derived, not fixed**, so plants stay meaningful at any size: boundary 5 per mille, NULLs 3 per mille,
   duplicates 3 per mille, erp exceptions 4 per mille (= 8 of 2000, i.e. the 99.5% budget), corrections ~1 per 300
   customers. `--small` = 200 customers / 5k events.
5. **Derived tables are not generated here.** `usage_by_load` (partitioned on insertion_time), the hash-partitioned table and
   the lookup table are schema details owned by D03, which can build them from `usage_events`/`accounts` with SQL. The world
   holds source rows only (AGENTS section 4 keeps the loader's schema in the loader).
6. **argparse, not typer**, for this module CLI: stdlib only, no dependency surface, and `python -m mdqm.testing.world` is the
   documented form.
7. **Committed tiny world** `tests/data/world/tiny_seed1.json` (12 customers, 2 months, 27 KB), so any change in generation
   shows up as a reviewable diff; regenerate with `pytest tests/unit/test_world.py --update-golden`.
8. Customer names are Hebrew (`דנה כהן`), and regions are canonical slugs (`north`, `center`, `tel_aviv`, `south`), so
   Hebrew/English synonym and value-map work has realistic data from day one.
