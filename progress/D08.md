## Summary
Added the hand-written golden SQL corpus and the test that validates it. `tests/data/queries/`
holds one file per dialect (`postgres.sql` 42 statements, `oracle.sql` 44, `tsql.sql` 44), blocks
separated by `-- ---`, each statement preceded by one `-- expect: {json}` line spelling out tables,
join edges (with conversion joins), filter columns, time columns, GROUP BY, aggregations, rounding
and scale expressions, and the now-like functions present. Every statement is a single read-only
SELECT short enough to review by eye, and the corpus deliberately carries the ugly cases: CTEs,
derived tables, correlated `EXISTS`, comments inside statements, quoted and bracketed identifiers,
Hebrew string literals, and dialect specifics (Postgres `now() - interval`, `::cast`,
`DISTINCT ON`, `FILTER`; Oracle `SYSDATE`/`SYSTIMESTAMP`, `ROWNUM`, `FETCH FIRST`, `TO_CHAR`,
`(+)`, `dual`; T-SQL `TOP`, `GETDATE()`/`GETUTCDATE()`/`SYSDATETIME()`, `[brackets]`,
`WITH (NOLOCK)`, `OFFSET ... FETCH`). `tests/unit/test_query_corpus.py` defines the
`ExpectedExtraction`/`JoinEdge` models, the block parser and the checks: every statement parses in
its dialect via `sqlglot.parse`, every expect block validates against the model, every listed name
really occurs in the statement it describes, ids are unique and dialect-tagged, no two statements
are identical, all statements are plain SELECTs, and each dialect has >=40 statements of which
>=10 carry a conversion join or a rounding/scale expression.

## Decisions
- **Names in an expect block are "as written, whitespace collapsed"**, and every list is compared
  order-insensitively. `tables` is the bare table name (schema/alias stripped); CTE names and
  derived-table aliases are not base tables, but a join edge may legitimately name one (pg-09,
  or-15, ts-12 join a CTE to a base table), and a correlated `EXISTS` equality counts as a join
  edge (pg-30, ts-25) because that is exactly the cross-source conversion the miner must see.
- **`rounding` also holds scale expressions** (`limit_k * 10`, `credit_limit::numeric / 1000`).
  D8 must rediscover granularity *and* order of operations, so `ROUND(x / 5000) * 5000` alone
  would under-specify the motivating case.
- **`now_functions` is a closed set** of non-deterministic time functions (`now`,
  `current_timestamp`, `current_date`, `localtimestamp`, `sysdate`, `systimestamp`, `getdate`,
  `getutcdate`, `sysdatetime`). Wrappers such as `ADD_MONTHS`/`EOMONTH`/`DATEADD` are not now-like
  and are not listed; a typo or a new invention fails the model instead of silently disagreeing
  with C02. `aggregations` is a closed set for the same reason.
- **Comparison must be order-insensitive**, so the corpus is not required to be sorted. Making
  sortedness a rule cost more review friction than it bought with 130 hand-written blocks.
- **No golden file under `tests/data/golden/`.** The corpus *is* the golden data; a generated
  summary file (counts, field inventory) would go stale on every added statement and AGENTS.md
  section "Docs: never hard-code fast-changing numbers" points the same way. The `golden` fixture
  stays for compiled-SQL output in later tasks (E03 and the compiler tasks).
- **File names are sqlglot dialect names** (`postgres.sql`, `oracle.sql`, `tsql.sql`) so C01/C02/S08
  can pass the stem straight to `read=`.
- **LF, UTF-8, no BOM**; the test rejects CRLF. Ids are `pg-NN` / `or-NN` / `ts-NN` and the test
  enforces the prefix so a block cannot be pasted into the wrong file unnoticed.
- The corpus is deliberately built on the synthetic organisation of AGENTS.md section 6
  (`crm.customers` rounded to 5000, `billing.accounts` raw, `erp.customers` rounded then /10,
  `usage_events` with `start_time`/`insertion_time`, `usage_by_load`, `accounts_hist`), so the
  expected conversions coincide with the ground truth the MVP must rediscover.

## Plan issues
- **`sqlglot` rewrites `now()` to `CURRENT_TIMESTAMP` on re-render** (verified while writing the
  corpus: `sqlglot.parse_one("SELECT now() - interval '7 days'", read="postgres").sql()`
  -> `SELECT CURRENT_TIMESTAMP - INTERVAL '7 DAYS'`). C02 must therefore detect now-like calls on
  the *original* text/AST input, not on a re-rendered string, and my `now_functions` values are the
  original spellings. Worth writing down in C02's task note.
- **`tests/data/queries/` had no owner of its loader.** C01, C02 and S08 all read this corpus, so the
  parser (`load_corpus`) and the models (`ExpectedExtraction`, `JoinEdge`) live in
  `tests/unit/test_query_corpus.py` as the task requires, but that module is importable from pytest
  only as `unit.test_query_corpus` (there is no `tests/__init__.py`). If a second consumer needs it,
  the clean fix is a small shared reader module under `tests/data/` (or `src/mdqm/testing/`), which
  is outside D08's `owns` list; until then, importing `unit.test_query_corpus` works from tests.
- **Oracle `(+)` outer joins** parse in sqlglot 30 but are deprecated in current Oracle; the corpus
  keeps one (or-40) because legacy views in the first organisation will contain them.
