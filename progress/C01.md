## Summary
`mdqm.sql.guard.guard(sql, dialect, policy=None) -> GuardResult` is the AST layer of the three-layer
read-only defence. One statement must parse (sqlglot, `error_level=RAISE`, `unsupported_level`
defaults to raising in the parser we call) and its root must be a SELECT, a set operation
(UNION/INTERSECT/EXCEPT/MINUS) or a parenthesised query. The whole tree is then walked for forbidden
nodes, so a Postgres data-modifying CTE (`WITH d AS (DELETE ...) SELECT ...`), `SELECT ... INTO`,
`FOR UPDATE`/`FOR SHARE`, `COPY`, `CALL`/`EXEC`/`EXECUTE`, `SET`/`BEGIN`/`COMMIT`, DDL, GRANT/REVOKE and
locking table hints are refused even when the root looks like a SELECT. A configurable denylist refuses
file/system/remote/sequence functions by name and by namespace prefix, including package-qualified
Oracle and T-SQL calls. A parse failure, an empty input, a NUL byte, a MySQL `/*! */` executable comment
and any multi-statement input are rejections, never allows. Rejections carry no AST and always carry an
`ErrorResponse` with a code, a problem and an exact `fix`.

## Decisions
* Three codes: `PARSE_ERROR` (unparseable/empty/NUL), `WRITE_BLOCKED` (any write, DDL, lock, command,
  denied function, or a root that is not a query), `MULTI_STATEMENT` (more than one statement). The task
  only named the first two; the third exists so the `fix` ("send one statement") is not drowned by a
  write message.
* Denial is by node type over the entire tree, not by the root alone: that is what catches
  data-modifying CTEs, `Lock` inside a subquery and `Into` in a nested SELECT.
* Function identity: a named `Func` reports its name via `sql_name()`; `Func.name` is the name of the
  *first argument* (`SUM(x)` -> `"x"`), so using `.name` would both miss denials and produce false
  positives on argument columns. `exp.Anonymous` (the node for every function sqlglot does not know)
  keeps the spelling in `this` and reports `sql_name() == "ANONYMOUS"`, so it uses `.name`.
* Oracle/T-SQL package-qualified calls (`DBMS_LOCK.SLEEP`, `SYS.DBMS_LOCK.SLEEP`, `UTL_FILE.FOPEN`)
  lose the package in the `Anonymous` node, so the qualifier of every `Dot` whose right side is a call
  is checked too.
* `pg_` and `sys_` are deliberately *not* blanket prefixes: `pg_typeof`, `pg_size_pretty`,
  `SYS_CONTEXT` and `SYS_GUID` are ordinary read-only functions. Only write/exec namespaces are
  prefixes (`dbms_`, `utl_`, `owa_`, `xp_`, `sp_`, `dblink_`, `lo_`, `pg_read_`, `pg_sleep`,
  `pg_create_`, `pg_drop_`, `pg_wal_`, ...), plus exact names (`sleep`, `nextval`, `setval`,
  `openrowset`, `sys_exec`, ...).
* Function names and table hints are compared after NFKC + casefold, so a quoted or full-width spelling
  (`"PG_READ_FILE"`, `ｐｇ＿ｒｅａｄ＿ｆｉｌｅ`) does not dodge the denylist.
* Two checks are textual because no AST can see them: a NUL byte (sqlglot silently drops it into an
  alias) and MySQL's executable comment `/*! ... */` (sqlglot treats the body as a comment, MySQL runs
  it).
* T-SQL table hints are an allow-list (`NOLOCK`, `READPAST`, `READUNCOMMITTED`), everything else
  (`UPDLOCK`, `XLOCK`, `TABLOCK`, `TABLOCKX`, `HOLDLOCK`) is refused: those take write locks on a
  primary database. `WITH (INDEX(...))` is not a `Var` in sqlglot and therefore passes; it is read-only.
* Rejections return `ast=None`: a caller must not be able to run a blocked statement by mistake.
* `GuardPolicy` (frozen dataclass: denied names, denied prefixes, allowed hints) is the "configurable
  denylist"; the tests show it in both directions (adding `sum`, and loosening `UTL_INADDR`).
* sqlglot 30 types: `exp.Expression` is a *subclass* of `exp.Expr`, and `sqlglot.parse` returns
  `list[Expr]`, so value types here are `exp.Expr`.
* `sqlglot.parse` returns `None` entries for empty statements (`SELECT 1;;` is one statement, not two),
  so `None` is filtered before counting statements.

## Deviations
* The task says "allow only a single SELECT / WITH...SELECT / UNION". `INTERSECT` and `EXCEPT`
  (Oracle `MINUS`) are also allowed: they are read-only set operations (`exp.SetOperation`), and the
  golden corpus uses `MINUS`. Blocking them would reject legitimate read queries for no safety gain.
* `src/mdqm/sql/__init__.py` (not in the `owns` list) was created because `src/mdqm/sql/` did not
  exist and is needed as a package. It contains only a docstring: re-exporting `guard` there would
  shadow the `mdqm.sql.guard` submodule (the same name), so the documented import is
  `from mdqm.sql.guard import guard`. C02 should add `exec_ts.py` next to it and keep that convention.
