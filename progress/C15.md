## Summary

Built `src/mdqm/governor/`: the layer that stops weak agents from hammering primary databases
(AGENTS.md principle 6). Five small modules plus the composer:

- `admission.py` -- three nested concurrency ceilings (global, per-user, per-source) taken in a fixed
  order and released in reverse inside a `finally`, plus a per-user fixed-window query quota. Peaks,
  in-use counts and wait totals are reported per scope. A caller that cannot get a slot within
  `max_wait_s` is refused with `QUOTA_EXCEEDED` naming the binding ceiling and when it frees up.
- `breaker.py` -- a per-source three-state circuit breaker (closed/open/half_open) driven by an
  injected clock. Opens after `failure_threshold` consecutive failures, admits exactly one trial
  after the cooldown, and short-circuits before the adapter is touched.
- `handles.py` -- `ResultStore` handing out opaque, owner-scoped, TTL-expiring `ResultHandle`s and
  paging them with `get_more(handle, offset, limit)` for the owner only.
- `core.py` -- `Governor.execute`: breaker -> slots -> quota -> deadline-checked drain -> store ->
  summary + handle. Every refusal is a `GovernorRefusal` carrying an `ErrorResponse`.
- `clock.py` / `refusal.py` -- the injected clock and the one agent-visible exception.

This reuses, and does not duplicate, F04 (`SourceAdapter`/`ArrowStream`), F05 (`FakeAdapter`),
F06 (`errors`), C16 (`summarise`/`ResultSummary`).

## Decisions

- **Quota is per-user query count, not the A05 token bucket.** `ratelimit.py` meters *request rate
  for API sources*; C15 needs a *budget of queries per user over a window*. Reusing the bucket would
  have conflated a per-source request rate with a per-user spend limit, so the quota is its own
  small fixed-window counter. A fixed window (not sliding) is deliberate: it has one nameable reset
  instant, which is what makes `QUOTA_EXCEEDED`'s `fix` actionable.
- **Cancellation happens in the drain loop, on the caller's thread.** The deadline is checked before
  each batch with the injected clock; when it passes the governor calls `adapter.cancel(stream)` --
  the adapter's real stop path -- then raises `TIMEOUT`. Nothing is abandoned: no worker thread is
  left running.
- **A blocking `execute` cannot be cancelled through this protocol.** `SourceAdapter.cancel` takes
  the stream `execute` returned, so before a stream exists there is no cancel key. This is a
  property of the F04 interface, not a gap I worked around silently: adapters must bound their own
  connect/execute time with `Limits.timeout_s` (the fake does). The governor's deadline covers the
  slow-stream case, which is the one that burns a primary's worker.
- **Concurrency refusal uses `QUOTA_EXCEEDED`.** There is no separate code in the closed F06 set for
  "too busy", and inventing one would break agents that branch on codes. The `quota`/`limit`/
  `resets_at` fields distinguish the three ceilings in the message and in `fix`.
- **Wrong-owner handles are indistinguishable from missing ones.** `HandleNotFound` never echoes the
  id, so two different ids produce byte-identical text; the id stays on the exception attribute for
  the server's own log. A test asserts this equality.
- **Slots are released when the refusal is raised**, not when a cancelled stream finishes unwinding,
  so one slow source cannot starve the others.

## Deviations

- Handles are **in memory only**, with `ttl_s`, `max_handles` eviction and a `max_rows_per_handle`
  cap, all reported through `ResultStore.stats()`. The task allows "on disk/in memory"; disk-backed
  spilling is not implemented. A result over the row cap is refused rather than silently stored.
