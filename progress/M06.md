## Summary

Filled in `POST /context`, the route the Claude Code plugin's `UserPromptSubmit` hook calls.
`src/mdqm/server/context_endpoint.py` owns the wire contract and the wiring; `app.py`'s route now
answers from it instead of returning the M01 stub. Request `{"prompt": str}` (max 4,000 characters,
extra fields refused), success `200 {"additionalContext": str}` and nothing else in the body.
`additionalContext` is `""` when no content word of the prompt matches the layer, which is the same
"empty is a normal answer" rule H05 encodes. The block is `build_pack(...)` — the H05 function M02
also calls — so the hook and `find_data` cannot drift. `serve()` builds the source from settings at
startup (`semantic_dir` + `metadata_db`), so a real deployment answers without extra wiring.

## Decisions

* **`ContextPackSource` is the seam.** A frozen dataclass of (layer, index, examples, budget) with
  `context_for(prompt)`, `build(layer, store=...)` and `from_directory(...)`. `M02`/`M03` can hold
  the same object; nothing in the endpoint knows how the layer was assembled.
* **Status codes, since "empty" cannot mean "unconfigured".** `401` from the transport for a bad
  token (unchanged from M01); `400` + `INVALID_SPEC` for a body the hook should not send (not JSON,
  missing/typed-wrong `prompt`, unknown field, prompt over the cap — all via
  `mdqm.errors.from_validation_error` on a `ContextRequest` model, so the text is the shared,
  scrubbed taxonomy); `503` + `NOT_SUPPORTED` when the deployment has no semantic layer yet; `200`
  with `""` when the layer has nothing relevant. The hook fails open on every non-200, so the split
  costs it nothing and makes a wiring bug visible instead of looking like "nothing matched".
* **Absence of a semantic layer is normal, corruption is not.** `context_source_from_settings`
  returns `None` (logged warning) when `paths.semantic_dir` does not exist — a fresh install serves
  the tools before bootstrap has approved anything — but a directory that exists and does not load
  raises out of `serve()`: a started server must not silently serve half a layer.
* **The prompt is bounded, not truncated.** A body over `MAX_PROMPT_CHARS` (4,000) is refused with
  the field named, instead of quietly reading the first N characters.
* **The block is not per-user.** It is semantic-layer text only, so the answer is identical for
  every authenticated caller; `Who` is not in the body and not needed to build it (the token never
  reaches the module at all).
* **One INFO line per call** with counts (`items`, `omitted`, `tokens_estimated`, `budget_tokens`,
  `semantic_version`) and no prompt text: what was injected is inspectable without logging a user's
  message.

## Not verified

* **Sockets in `tests/unit`.** The module is marked `pytest.mark.enable_socket` with an autouse
  `socket_allow_hosts(["127.0.0.1"])`, exactly like `tests/unit/test_mock_api.py`. The reason is
  Windows, not the network: asyncio's Proactor loop builds its self-pipe from `socket.socketpair`,
  which Python implements with a real `AF_INET` socket on Windows, so merely creating a loop trips
  `pytest-socket` (the comment is in the file). Every request goes through
  `httpx.ASGITransport(app=server.streamable_http_app())` on `http://mdqm.test` — no port is bound,
  nothing leaves the box. The one place a real socket is used is the pristine M01 module, untouched.
* **A real Claude Code hook.** `plugin/mdqm/` does not exist yet (that is M07), so the request shape
  is the one `TASKS.md`/`DESIGN.md` specify (`{"prompt"} -> {"additionalContext"}`) and is not
  proven against a live plugin install.
* **A production semantic layer.** The tests build the layer in code (H05's shape) and through a
  one-file `semantic/generated/` directory; nothing here was run against a pipeline-written layer
  over the D02 world, because that needs the integration services this box cannot start.
* **`--require-services` integration runs**: not attempted (no container runtime on this machine).
