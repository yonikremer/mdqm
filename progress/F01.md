## Decisions
- **`check.py` stays lint-only (no `ruff format --check`).** Five files would be reformatted today:
  `docs/DESIGN.md`, `scripts/integrate.py`, `scripts/next_tasks.py`, `scripts/render_tasks.py`,
  `scripts/tasks_def.py`. None is owned by F01 and `scripts/tasks_def.py` is explicitly forbidden to edit,
  so adding the step would have made `scripts/check.py` red on `main` and forced edits into other lanes.
  Recorded here instead of silently reformatting someone else's files.
- **CI installs `.[dev]`, not `.[dev,pg]`.** The unit suite touches no database and driver extras are
  gated per adapter; installing `psycopg[binary]` here would let one missing cp313 wheel fail all four
  jobs. When adapter A02 starts importing psycopg, that task should widen the CI install.
- **No dependency pin changes.** `pip install -e ".[dev,pg]"` already resolved in the venv
  (Python 3.12.15), so the "fix a resolution error" escape hatch was not needed.
- **`types-PyYAML` without `PyYAML` left alone.** Nothing imports PyYAML yet (validating the workflow used
  `ruamel.yaml`, which is a real dependency); removing the stub is a pin change the task forbids, so it is
  only flagged under Plan issues.
