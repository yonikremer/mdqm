## Summary
`src/mdqm/semantic/` implements the frozen semantic layer and its loader for
`examples/semantic_example.yaml`: `version`, `sources`, `defaults` (cache rule, quiet windows),
`value_maps` (canonical values, both-language synonyms, per-source codes), `measures` (canonical
rounding + per-source `normalize` template), `tables` (key, default window, partitioning, time
columns with role/indexed/use_by_default/lag, mutability class + status, cache override) and
`approved_joins` (cardinality, usage, provenance). Every item can carry `provenance`.
`mdqm.semantic.load(path)` takes one file or a directory and merges `generated/*.yaml` then
`curated/*.yaml`, curated winning per key, so deleting a curated key restores the generated value.
`SemanticLayer.version_hash` is a SHA-256 of the validated content (comments, layout and key order
cannot reach it) and fills itself on any construction. Validation errors name the file, the dotted
path and the line, via ruamel's round-trip line info; a misspelled field suggests the real one.
`mdqm.semantic.writer` rewrites `generated/<section>.yaml` atomically and updates curated files
in place while keeping their comments. Hebrew is first-class: `normalize_label` does NFKC, strips
niqqud, folds geresh/gershayim variants, removes zero-width characters, casefolds and collapses
whitespace; value-map lookups work for Hebrew labels, English labels and source codes.

## Decisions
- **Merge is recursive, curated wins per leaf.** A curated file that sets only
  `tables.X.mutability` keeps every other generated fact about `tables.X`; a list replaces
  (never concatenates), except `approved_joins`, which merges per `name` so a curated file can
  change one join's `cardinality` without repeating its `on` clause.
- **An empty section in a curated file means "nothing to override here"** (`tables.X:` with no
  value) instead of erasing the generated node.
- **Immutability is enforced at runtime, not only by pydantic.** Container fields are a
  `FrozenMapping` (a `dict` subclass whose mutators raise `TypeError`), so `layer.tables[k] = v`
  and `.update()` fail; a plain dict inside a frozen model is still mutable.
- **Line attribution follows the winning file.** Merging happens in place (that keeps line
  numbers), and origins are tracked per container and per key, plus a hint to the winning node, so
  a bad curated value reports `human.yaml: line N` rather than the generated file that supplied the
  surrounding block.
- **`version_hash` is a real field filled by a model validator**, so a layer built by hand (tests,
  a pipeline stage) also gets a correct hash; a YAML that *contains* `version_hash` is rejected by
  `extra="forbid"` — the hash is derived, never an input.
- **Mutability: a cacheable class needs `status: approved` to be cacheable.** `may_cache` is True
  only for an approved `append_only`/`append_rarely`; `unknown` is accepted at load time (it is
  what an unclassified table is) but is never cached. Rejecting unapproved cacheable classes at
  load time would block loading generated proposals, so the check lives in `may_cache` instead.
- **`sources` does not re-validate that a `source.table.column` prefix is a declared source.** A
  deployment may declare sources in `mdqm.yaml` settings rather than in the semantic file; a false
  rejection there is worse than the missing check, and the D1 catalog is the real authority.
- **A literal credential in `sources` is a validation error by construction** (`extra="forbid"`
  plus `secret: <name>` refs), so `find_literal_secrets` is not run over the whole document: a
  legitimate value-map column such as `crm.users.password` must not be rejected.
- Reused existing code instead of duplicating it: `mdqm.cache.freshness` (`Mutability`,
  `CACHEABLE_MUTABILITY`, default TTLs), `mdqm.models.partitioning.Partitioning` (the file's short
  form `{key: col}` / no `strategy` is normalised into it), `mdqm.config.quiet.QuietWindow`,
  `mdqm.config.settings.{AuthSettings,LoadLimits,RateLimitSettings}` and `check_secret_name`.
