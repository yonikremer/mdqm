## Summary
`src/mdqm/linter/` is a rule registry over the query spec (the primary path) and over raw SQL (the
emergency exit). Sixteen rules, each a small class with an id, a severity, an auto-fix flag, a target
and a tuple of declared before/after cases:

| id | behaviour |
|---|---|
| `spec.table` | refuses an unknown table with "did you mean" |
| `spec.join` | refuses an unknown join, or one that does not touch the table the spec reads |
| `spec.measure` | refuses an unknown measure, listing the measures that exist |
| `spec.column` | refuses an unknown column with "did you mean"; a column only another table has is refused with the approved join and its full `ON` clause |
| `spec.categorical_ordering` | refuses `gt`/`lt`/`range`/`contains` on a value-mapped column |
| `spec.value` | auto-fixes a Hebrew/English label or a source code to the canonical value (Hebrew label for 'active' -> `active`, reported in `applied_fixes`); an unknown label is refused with the valid values, an ambiguous one with its candidates |
| `spec.raw_column_measure` | refuses a raw source column that a measure covers in non-canonical units, naming the measure to select |
| `spec.insertion_bound` | auto-fixes the derived event-time bound for a filter on the ingestion column (original predicate kept); refuses when no lag is approved or verified |
| `spec.partition` | refuses a table that requires a partition-key filter and has none (same code, window and scan estimate as C08) |
| `spec.limit` | auto-fixes a missing `limit` to the server row cap |
| `sql.guard` | refuses a write, DDL, command or second statement (via the taxonomy) |
| `sql.table` | refuses an unknown relation with "did you mean"; a CTE, a table function, a case variant and a declared `extra_relations` entry are not unknown |
| `sql.now` | auto-fixes `now()`/`CURRENT_TIMESTAMP`/`SYSDATE`/`GETDATE()` to one absolute `exec_ts` |
| `sql.limit` | auto-fixes a missing `LIMIT` |
| `sql.value` | auto-fixes a categorical label compared with a stored column to the code(s) that column holds (`=` or `IN`); refuses a label the column cannot store |
| `sql.partition` | auto-fixes the key predicate the partition planner proved (default window, or a range replacing a function/cast on the key); refuses the scan the planner refuses |

Every rule is a pure function of `(LintState, LintContext)`; `RuleOutcome` refuses an outcome that
fixes without a sentence or both fixes and refuses. `LintContext` carries the semantic layer, the
catalog columns, the single `exec_ts`, the dialect, the caps and the declared extra relations.

`Registry` is built at import and rejects a rule with no cases, no firing case, no silent case, an
auto-fix and no case showing its output, an `error` severity and no case asserting the refusal code,
or a firing case that does not assert its message -- so a rule without a test cannot reach `main`
(the package fails to import). `tests/unit/test_linter.py` replays every declared case, both
directions, and adds: the idempotence invariant for five specs and five statements, "a fixed spec
still re-validates through `parse_spec`", a hypothesis property that the value rule never invents a
value outside the value map, and a fixed-point run over the whole three-dialect SQL corpus in
`tests/data/queries/`.

## Decisions
- **`applied_fixes` wording matches the compiler's.** `spec.limit` says exactly what
  `CompiledQuery.applied_fixes` says for the same fix, so an answer that merges both lists does not
  repeat a different sentence for the same change.
- **The linter refuses, it does not repair, where the spec cannot express the repair.** A raw column
  that a measure covers is refused with the measure's name instead of being replaced by an
  aggregation the agent never asked for (that would change the answer). The same reasoning keeps the
  unapproved join and the ambiguous value as refusals: `RuleOutcome` makes "fix and refuse" impossible.
- **Division of labour with the planners.** The default partition window and the event-time predicate
  of a time intent are injected and reported by C07/C08 during compile, so the spec rules stay silent
  when a table allows that injection and refuse only the case C08 would refuse. The raw-SQL path has
  no planner, so there `sql.partition` injects the predicates C08 builds and reports the planner's own
  sentence.
- **Raw SQL is checked where a static check cannot be wrong.** Unknown columns, join approval and the
  ingestion-time derived bound are left to the spec path (and, for columns, to the source): `ORDER BY`
  on an output alias, a dialect expression or a correlated subquery all look like an unknown column,
  and a wrong refusal blocks a valid query. Documented in `sql_rules.py`.
- **Case-insensitive relation matching and `extra_relations`.** Oracle folds an unquoted identifier to
  upper case, so `"CRM"."CUSTOMERS"` is `crm.customers`; `dual` is declared by the deployment rather
  than guessed by the linter. Both decisions came from running the linter over `tests/data/queries/`.
- **`sql.value` handles `=` and `IN`.** A label inside an `IN` list would silently match nothing,
  which is the failure mode DESIGN section 5 forbids, so the same rule rewrites both shapes.

## Deviations
- **`src/mdqm/linter/` is not wired into the compiler.** The task owns only the linter package and its
  test file, and `src/mdqm/compiler/core.py` (lane C09) is not in `owns`. The two `applied_fixes`
  contracts are shaped alike (`CompiledQuery`, `LintResult`) so the server can call `lint_spec` before
  `compile_spec` and concatenate the reports; that wiring is a follow-up outside this task's files.
- **`spec.raw_column_measure` refuses instead of auto-fixing.** TASKS.md lists it under the auto-fix
  examples and DESIGN section 5 as "replace with the measure and per-source normalisation". The spec
  has no way to say "this column, normalised": a measure is an aggregate, so replacing a plain
  selected column with one would invent an aggregation and change the answer. The rule refuses with
  the measure name in the `fix`; the meaning-preserving auto-fix for the same data lives in
  `spec.value` (labels) and in the compiler's measure normalisation.
- **The partition default window is auto-fixed only on the raw-SQL path.** On the spec path C08
  injects it at compile time and reports it there; auto-fixing it in the linter as well would produce
  two different window predicates for one request. Recorded as a decision, not a gap: the spec path
  still refuses every scan C08 refuses.
- **No golden file for linted SQL.** `tests/data/golden/` belongs to D08 and is not in this task's
  `owns`; the repaired SQL is asserted with `expect_sql` fragments and by the fixed-point run over the
  existing corpus instead.
- **TASKS.md acceptance "at least 12 rules"** is met with 16; each rule ships at least one firing case
  asserting its message and one silent case, both replayed by the test suite.

## Not verified
- **Nothing ran against a real database.** The linter is pure logic and was proven by parsing,
  planning and rewriting in-process, plus a fixed-point run over the 130 statements of
  `tests/data/queries/{oracle,postgres,tsql}.sql` (all three dialects). The one fix whose effect only
  a real source can confirm is `sql.partition`'s injected window on a live monthly-partitioned table:
  the predicates are the ones C08 already proves, but no plan was counted here. No container runtime
  exists in this environment (no Docker/WSL2), so no integration test could run.
- **Elasticsearch/API lane.** The linter covers spec and SQL input only; the ES and OpenAPI request
  shapes are not spec or SQL and are out of this task's scope.
