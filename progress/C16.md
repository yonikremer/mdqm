## Summary          Built `src/mdqm/results/summary.py`: `summarise()` turns a `pa.Table`, a single
                     `RecordBatch` or any iterable of batches (an adapter's `ArrowStream` qualifies)
                     into one frozen `ResultSummary`: `rows_total`, counted drops (`rows_not_shown`,
                     `truncated`), a labelled sample of at most `sample_rows` rows, per-column stats
                     (nulls, distinct + how exact, min/max) and an actionable handle plus a copy-ready
                     `next_call`. Token estimation is dependency-free and conservative: ASCII at
                     chars/4, everything else at chars/2.5 (Hebrew counted worse than English).
                     The summary shrinks itself -- statistics first, then sample rows -- until the JSON
                     the agent receives fits the budget, and always reports the estimate it applied.
## Decisions        - Budget defaults live as module constants (4000 default, 25000 hard cap, 512 floor)
                     and every one is an explicit argument, so F03 config passes its own values; the
                     core does not read config. A request outside [floor, cap] is clamped and
                     `budget_clamped: true` says so instead of silently ignoring the config.
                   - `distinct` is computed over at most 200,000 rows (Arrow `count_distinct` takes 1.8s
                     on 10M distinct int64, which alone blows the 1 second acceptance). The result is
                     labelled `distinct_kind: exact|lower_bound|unavailable` -- a slice can only
                     under-count, so it is never presented as exact.
                   - Statistics cover the leading `max_stat_columns` (default 8) columns; min/max are
                     exact over the whole table (Arrow is fast at it) rather than sampled, because a
                     min over a sample is not a min. Unordered types report `null` bounds instead of
                     failing.
                   - Shrink order is statistics first, sample rows second: one sample row carries more
                     meaning per token for a weak agent than a min/max pair. Row count and handle are
                     never dropped, so the answer is always actionable.
                   - `handle` is an optional caller argument (the governor's registry key, a later
                     task); when omitted it is derived from schema + row count via sha256, so the
                     output stays clock- and randomness-free and deterministic.
                   - Sample values are converted without formatting: floats stay JSON numbers (no
                     rounding drift), NaN/inf become null (JSON cannot hold them), timed dates become
                     ISO strings, decimals stay exact strings, bytes decode as UTF-8 or fall back to
                     hex.
                   - `tokens_estimated` is part of the JSON it measures, so it is settled by
                     iteration until the reported number equals the measured size -- that is what lets
                     the guarantee be stated on the full `model_dump_json()`.
