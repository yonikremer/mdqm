## Summary
Capability probe framework under `src/mdqm/probe/`, built around F02's `Capabilities`/`Capability`
(tri-state `supported: bool | None`, `source: probed|override`) instead of a parallel model.

- `features.py` — the one catalogue from DESIGN section 4: feature -> capabilities it needs -> its
  fallback. `fallbacks_for()` turns verdicts into the degraded-feature list, keeping `unsupported`
  and `unknown` apart (both block a feature, but they mean different things).
- `runner.py` — `ProbeRunner` guards every call with a timeout. `Adapter.probe()` raising
  `NotSupported` records that capability `unsupported` with the adapter's detail; any other
  exception or an overrun records every optional capability `unknown` with a masked, clipped
  detail. Per-feature hooks (metadata store) each get their own timeout. Nothing propagates.
- `overrides.py` — `overrides.yaml` (`defaults` + `sources`), each entry `true`/`false`/`null` or
  `{supported, detail}`. Errors name file + key path + YAML line and never echo a value.
- `merge.py` — the override wins, `source=override`, and the detail always says
  `admin override[: <why>] (probe said <state>)`.
- `report.py` — `generated/capabilities.yaml` via `semantic.writer.write_generated` (atomic,
  deterministic, sorted sources and capability names), the per-source fallback list, and
  `diff_reports()` producing `changed: ["crm.explain_plan: supported -> unsupported", ...]`.
- `run.py` — one run: adapters -> merge -> report -> diff, plus the metadata-store probe hook
  (FTS5 through `store.db.check_fts5().capability()`, so H01 can add probes without new plumbing).
- `cli.py` — `mdqm probe [--source] [--root] [--overrides] [--timeout]`, registered in
  `src/mdqm/cli.py` with a two-line edit (see Deviations).

Three golden files (`capabilities_minimal/declared/mixed.yaml`) cover acceptance 1; 64 table-driven
tests cover all three capability states, the override-wins merge, re-probe survival, the diff in
both directions, raise/timeout behaviour, credential masking and the CLI.

## Decisions
- **Tri-state, three distinct states in the report.** `unknown` also triggers the fallback (per
  F02's docstring, "None never means failure: the caller takes the declared fallback"), but the
  report records the state that caused each gap, so "cannot" and "nobody asked" never blur.
- **Timeouts via a thread pool `future.result(timeout=...)`.** The only OS-agnostic option
  (`signal.SIGALRM` is unavailable on Windows and main-thread-only elsewhere). A timed-out call is
  abandoned, not killed; `max_workers=4` bounds the leak and a `shortcut:` comment marks the
  upgrade path.
- **Failure detail is masked, not dropped.** A driver message can carry a DSN, so `://user:pw@`
  and `password=`/`token=`-shaped text is masked, control characters stripped, 160 chars max.
  Drivers' real diagnostics ("ORA-00942") survive; secrets do not.
- **The configured source name is authoritative.** `probe()` may know itself by `kind`; the report
  is keyed by the name in `mdqm.yaml`, because that is what an operator and the overrides file use.
- **A corrupt `generated/capabilities.yaml` raises `ConfigError` naming the file**; the CLI prints
  it as a warning and regenerates. The artifact is machine-written, so hand damage is a bug, but it
  must not block the nightly probe.
- **`--json`/`--fail-on-change` flags were not added.** Not in the task; a diff is already printed.
- **The probe seam is narrower than `SourceAdapter`.** `ProbeRunner.probe_adapter` takes a
  `ProbeTarget` (a single `probe()` method) and the caller passes the configured `name` and the
  adapter `kind`. Probing never touches catalog/execute, so a two-line test double is a valid
  argument and the report still uses the operator's name.
- **`overrides.yaml` is read with ruamel `typ="rt"`, kept deliberately.** Line numbers in errors
  are required, and only the round-trip loader records them. Verified empirically: the
  `!!python/object/apply:os.system` payload does **not** execute (`RoundTripConstructor` derives
  from `SafeConstructor`), so the ast-grep "insecure deserialization" hint is a false positive for
  ruamel. The plain `typ="safe"` loader refuses such tags but loses line numbers.
- **The golden files normalise the DuckDB version string** to `duckdb-<installed>`. The installed
  build is environment-dependent and a golden that pins it would fail on the next machine; every
  other byte of the artifact is fixed by the injected clock.
- Timestamps in goldens come from an injected `FixedClock` (2026-01-01T12:00:00Z), never the wall
  clock.

## Not verified
- **No live probe of a real database.** This machine has no container runtime and no
  Postgres/Oracle/SQL Server/Elasticsearch, so `probe()` was exercised against `FakeAdapter`
  (F05), stub adapters and the in-process metadata store only. The framework's behaviour for a
  driver that refuses a feature, raises, or hangs is covered by tests; whether a given real
  driver's `probe()` reports correctly is A02's and later adapters' business.
- **The timeout/abandon path under a genuinely wedged C-extension call** (driver stuck in
  native code forever) was not exercised — the test sleeps in Python. A hung native call keeps a
  thread alive past `close()`, as documented in the `shortcut:` comment.
