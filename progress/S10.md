## Summary

`src/mdqm/llm/` is new: a stdlib+`httpx` client for an on-prem OpenAI-compatible
`/chat/completions` endpoint, plus its probe, its cache and a test double.

- `client.py` — `ModelClient`: `structured(prompt, schema)` asks for one closed JSON object,
  validates it with pydantic in code, sends the validation error back on a rejected reply, and
  records every attempt. `temperature=0`, timeouts/retries from `ModelSettings`, exponential
  backoff with an injected clock and sleep function, `models()` for the model list.
- `probe.py` — measures `reachable`, `structured_output`, `tool_calling`, `context_window` and
  returns a `Capabilities` whose `source` is `model_endpoint` (reuses the F02 model, no second
  shape). An unreachable endpoint stops after one call instead of firing four doomed ones.
- `result.py` — `Attempt`/`LLMResult`/`StructuredLLM` protocol: the value, the attempt trail, the
  model, the prompt version, `cached`, `fetched_at`.
- `cache.py` — `ResponseCache`: SQLite (stdlib, WAL) keyed by a SHA-256 of the *input*; only the
  raw JSON text is stored and every read re-validates, so a changed schema can never be served.
- `errors.py` — `ModelError` with `code`/`problem`/`fix`/`retryable`/`status_code`/`attempts` and
  `to_error_response()`, so the server can hand it to an agent verbatim.
- `fake.py` — `FakeLLM`: scripted replies (schema instance, mapping, JSON text, exception,
  callable), validates them, records each call, fails loudly when the script runs out.

## Decisions

- **`response_format` only when probed True.** Tri-state on the client (`True`/`False`/`None`);
  `None` and `False` take the instruct-and-validate fallback. A server that refuses
  `response_format` at call time downgrades the client for later calls (one wasted retry, not
  one per call), and the refusal is visible as `response_format_rejected` in the attempt trail.
- **The schema is always spelled out in the system prompt** (even when `response_format` works),
  so one prompt shape serves both paths and the fallback is never a surprise. It costs a few
  tokens; determinism is worth more than that.
- **Cache key = SHA-256 of {base_url, model, prompt_version, prompt, system, schema}** — never the
  key. `prompt_version` is recorded for traceability; the prompt text is hashed anyway, so a
  changed template cannot hit a stale row.
- **Retry budget is one number** (`model.max_retries`) covering transport errors, timeouts,
  retryable statuses and invalid output: `1 + max_retries` calls in total. Chosen over separate
  budgets because protecting the endpoint matters more than fine-grained retry policy.
- **Backoff** is `backoff_s * 2^(n-1)`, capped at 30 s (`backoff_s` defaults to 1 s). `ModelSettings`
  has no backoff field and config is F03's file, so it is a constructor argument; note for F03/A-lane
  if it should move into settings.
- **Cache path** is `Settings.paths.cache_dir / "llm_cache.sqlite3"`; an explicit `cache=` wins.
  It is its own SQLite file, not a table in `mdqm.store` (H01's), so the lanes stay separate. Each
  call opens its own connection, so threads and processes cannot corrupt it.
- **Unconfigured endpoint fails loudly** at construction with `MODEL_NOT_CONFIGURED` rather than
  defaulting a model name or a URL: both are unknown facts about an unverified server. The
  message and fix name the env vars, never a value.
- **API key resolution order**: constructor `api_key` > `settings.model.api_key` (env/secret file
  via `SecretStr`) > `SecretProvider.get("model_api_key")`. The reference name is a constant
  (`DEFAULT_SECRET_NAME`), overridable; it is a name, never a value.
- **Redaction**: any server error text is passed through key redaction before it can reach an
  exception, so a server that echoes the Authorization header cannot leak it.
- **Probe verdicts are conservative**: 4xx refusals are `False`, auth failures/429/5xx/transport
  are `None` (unknown), and an accepted `response_format` answered with prose is `None`, not
  `True`. `False`/`None` both fall back safely; only a measured success claims support.
- `context_window` keeps the token count in `Capability.detail` (plus `context_window()` to read
  it back) so the whole probe result stays one `Capabilities` object.

## Deviations

- The prompt said `docs/DESIGN.md` has a "model client" section; it does not. DESIGN section 10
  defines the contract this implements ("closed JSON output validated in code, up to 2 retries
  with the error, temperature 0, prompt versions + model name stored"). No design change was made,
  so DESIGN.md was not touched.
- Error codes (`MODEL_NOT_CONFIGURED`/`MODEL_TIMEOUT`/`MODEL_UNAVAILABLE`/`MODEL_HTTP_ERROR`/
  `MODEL_OUTPUT_INVALID`) are defined in `llm/errors.py`, not in a shared registry: no registry
  exists on `main` yet (F06 may add one). They are the names to register when it lands.

## Dependencies

None. `httpx` (already a dependency) and stdlib (`sqlite3`, `hashlib`, `json`, `re`, `logging`)
cover everything; no vendor SDK, no retry library.

## Not verified

- **No live endpoint call.** This box has no reachable on-prem GLM-family server (and no
  container runtime), so real compatibility is unproven: `response_format` with `strict: true`,
  the `/models` shape, and how the real server reports a refusal. Everything is exercised against
  an `httpx.MockTransport` scripted to all three plausible behaviours, and the client falls back
  safely when the guess is wrong. First integration run against the real endpoint is the check
  A-lane needs to do: `probe_model_endpoint` reports what it actually found in one call.
- Whether the real server accepts `temperature: 0`, and its behaviour on an empty `choices` list:
  both are handled defensively and reported as attempt outcomes.
- No integration test: `tests/integration` needs Docker services and S10's acceptance is unit-level.
