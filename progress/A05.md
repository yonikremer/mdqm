## Summary
- `src/mdqm/ratelimit.py`: thread-safe token-bucket limiter in which **one pool is shared by every
  API source by default**, with each source keeping its own sub-limit bucket. `shared_pool: false`
  in a source's config is the per-source opt-out.
- `acquire()` returns a `Decision` (granted/denied, `wait_s`, `jitter_s`, which `pool` bound it,
  its `limit_rps`, and any running `Retry-After` pause) with `DecisionReason`
  `unlimited|ok|throttled|retry_after|denied`. A denial consumes no token and is rendered for the
  agent by `denial_error()` through the existing `errors.quota_exceeded` builder (no new code).
- `report_429(source, retry_after)` pauses every bucket the source draws from, i.e. the whole
  pool; the pause freezes the refill so tokens spent before the 429 are not handed back for free.
  `parse_retry_after()` reads both RFC 9110 forms (delta-seconds, HTTP-date with an injected `now`).
- Time is fully injected (`TimeSource.now`/`sleep`); `SystemTime` is the only wall-clock contact.
  Metering is a reservation (debit, then sleep outside the lock), so concurrent callers queue.
- `from_settings()`/`limits_for_sources()` build the buckets from the existing
  `RateLimitSettings` — no new config field and no edit to another lane's file.
- Observability: `snapshot()` returns per-bucket tokens, pause remaining, granted/denied/waited.

## Decisions
1. **Bucket starts empty** (banks nothing at start-up). This is what makes "100 requests at rps=2
   take 50 s of fake time" exactly true, and it is the conservative reading of principle 6: a
   cold process does not get a free burst at the source's expense.
2. **Shared pool total = the smallest member `rps`** when the operator has not supplied one
   (`shared_pool_rps` overrides). Settings has no field for an organisation-wide API budget, and
   §9 says the real budgets are unknown, so the pool never hands out more than any single member
   declared for itself. `RateLimitSettings` gained no field: burst/jitter/`max_wait_s` live in the
   limiter's own `LimitPolicy`, so no other lane's file was touched.
3. **Metering by reservation** (debit before sleeping) rather than a "check, sleep, re-check"
   retry loop: no lost updates, no thundering herd, and `reserve()` is the whole logic without the
   sleep — which is what the frozen-clock thread test and any caller that would rather report the
   wait than block use.
4. **A 429 without `Retry-After` pauses one burst window** (`burst / rps`): the shortest back-off
   that still refills the bucket, instead of guessing a number.
5. **Jitter defaults to 0** (determinism first, principle 3) and is driven by an injected, seeded
   `random.Random`; it is added only to the sleep, so it can never push past the rate.
6. **Deny instead of block is opt-in** (`max_wait_s`, default `None` = always wait): a shared
   conservative limiter should slow callers down, and a caller that cannot afford a blocked thread
   says so. The boundary is inclusive (`wait == max_wait_s` is granted).
7. `granted` is counted on every bucket that handed out a token, `waited_s` only on the bucket
   that determined the wait, `denied` only on the bucket whose cap was exceeded — so
   `snapshot()` numbers add up and a throttle is explainable.

## Deviations
- The task text says "async token bucket"; the limiter is **synchronous and thread-safe**, with a
  thin `acquire_async()` (`asyncio.to_thread`) for the async server. `AGENTS.md` section 3 says
  adapters are synchronous and run in a bounded thread pool behind the governor, and the scheduler
  requirement in this task says "thread-safe", so a sync core is the shape the server needs; the
  async face keeps the option open. No acceptance criterion mentions async.
- `tests/unit/test_ratelimit.py::test_acquire_async...` carries `@pytest.mark.enable_socket`: on
  Windows the proactor event loop builds its self-pipe from a `socketpair`, so `asyncio` cannot
  start under the unit-test socket block. The test never connects anywhere. This is the loopback
  opt-in AGENTS.md section 6 allows.
