## Decisions
- **T-SQL week buckets are refused** (`INVALID_SPEC`, field `group_by.N`, fix lists the other
  units). A T-SQL week starts wherever the session's `DATEFIRST` says, so the same statement means
  a different week per connection: a wrong number, not a slow one. PostgreSQL and Oracle both mean
  the ISO Monday, so they keep the bucket (Oracle `TRUNC(x, 'IW')`).
- **Oracle gets explicit literals**: `CAST('...' AS TIMESTAMP)` reads `NLS_TIMESTAMP_FORMAT`, so the
  same SQL means a different instant on a differently configured session. `TO_TIMESTAMP` with a
  mask is session-independent. T-SQL likewise gets the `T`-separated ISO form, the one
  `SET DATEFORMAT` cannot re-read.
- **`LPAD` is translated for T-SQL, not refused.** The semantic join template pads a key
  (`LPAD(cust_id, 10, '0')`); T-SQL has neither `LPAD` nor `RPAD` and sqlglot passes the name
  through, which is a guaranteed "Invalid object name". `RIGHT(REPLICATE(fill, n - LEN(x)) + x, n)`
  is the textbook equivalent, so all three C09 specs produce real T-SQL SQL.
- **T-SQL truncation uses `DATETRUNC`** (SQL Server 2022+, compatibility 160). Recorded as a
  `shortcut:` in the module: an older instance needs a `DATEADD`/`DATEDIFF` form there.
- **Oracle bucket masks are ours, not sqlglot's**: sqlglot renders `TIMESTAMP_TRUNC(...)` for Oracle
  (no such function) and `TRUNC(x, 'WEEK')` for a week (not a valid Oracle mask; `'IW'` is).
