## Summary
`src/mdqm/eval/harness.py` answers every E01 question twice -- the curated **spec** path (compile + run
against the real source) and E01's **oracle** SQL (executed directly) -- and scores both against the
ground truth, printing a table and a machine-readable report. The model leg deliberately lives in
`scripts/bench_glm.py` so a harness run is deterministic and needs no endpoint.

## What it found (the reason this is `partial`, not `done`)
Two assumptions in the E01 fixture disagree with the D03 database layout. Neither is a harness bug;
both are real inconsistencies in the repo that the harness exposed:

1. **`erp.customers` column name.** The live table has `cust_no, name, status, limit_k`; E01's oracle
   SQL and `examples/semantic_example.yaml`'s value map both say `status_code`. The oracle leg for the
   two erp questions therefore fails with `UndefinedColumn`, and the spec leg answers through a
   column the curated layer names differently.
2. **Oracle SQL is schema-qualified by source.** E01 writes `billing.usage_events`,
   `crm.customers` -- i.e. it assumes one database with one schema per source. D03 loads three
   **separate databases** whose tables live in `public`, so the oracle leg fails with
   `UndefinedTable`. The product's own layer maps source -> database at the connection, not in SQL.

Both are fixable (rename the erp column in the loader, or rewrite the oracle SQL per database), and
until one of them is chosen the harness cannot report a truthful 15/15.

## Evidence
- Each verdict prints `spec` and `oracle` plus the failure detail; e.g.
  `customers_by_region_crm rows PASS ERROR UndefinedTable: relation "crm.customers" does not exist`.
- `churned_customers_hebrew` and `customers_by_region_crm` pass on the **spec** path, which shows the
  pipeline itself is answering the question while the oracle leg is the one that cannot run.

## Decisions
- The harness reuses `scripts/bench_glm.py`'s scorer instead of writing a second comparison: one
  definition of "matches ground truth" for both the offline and the model benchmark.
- A failing leg is reported per question, never swallowed: `ERROR` carries the driver's message.
