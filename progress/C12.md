## Summary

`src/mdqm/cache/freshness.py` holds the freshness rule as pure logic: no I/O, no sleeping, no global
clock. `is_fresh(age, range_from, range_to, *, theta, min_ttl, max_ttl, mutability, short_ttl,
sealed, verified)` implements `age <= min(max(min_ttl, theta*span), max_ttl)`; `ttl_for(span, ...)`
exposes that boundary so a refetch can be reported as "age 1d > ttl 1.68h"; `is_fresh_at(fetched_at,
clock, ...)` is the cache-read entry point and reads "now" from an injected `Clock` protocol
(`SystemClock` in production, a test-local `FixedClock`). The design's worked example is a test: a
1-year pull from yesterday is fresh (TTL 3.65 days), a 1-week pull from yesterday is stale (TTL
1.68 hours). `tests/unit/test_freshness.py` covers the worked example, the `min_ttl` floor, the
`max_ttl` ceiling, the inclusive boundary, the mutability policy, sealed segments, rejected inputs
and the clock path, plus hypothesis properties for monotonicity in age, "a wider range is never
less fresh", "unclassified tables are never fresh", and "`ttl_for` and `is_fresh` cannot drift".

## Decisions

- **Boundary is `<=`.** `age == ttl` is fresh, `age == ttl + 1µs` is not. Stated in the docstring
  and pinned by `test_ttl_boundary_is_inclusive` (a parametrized table over all three TTL regimes)
  and by the `ttl_for` property test.
- **`max_ttl` also caps a configured `short_ttl`.** A per-table short TTL of 30 days on a
  `mutable_critical` table is a misconfiguration; the global ceiling wins (conservative).
- **Negative `age` raises `ValueError`.** `age = now - fetched_at` cannot be negative unless
  `fetched_at` lies in the future, which is clock skew or corrupt metadata. Raising keeps the
  function's domain at `age >= 0`, which is exactly the domain the monotonicity property is stated
  over. The cache read path therefore uses `is_fresh_at`, which returns `False` (refetch) for a
  future `fetched_at` instead of raising: a refetch is cheap, serving a segment of untrusted
  provenance is not.
- **`sealed=True`** marks a closed partition segment: the ratio rule is skipped and only
  `max_ttl` bounds it, with `verified=False` (the nightly check saw an unexpected change) forcing a
  refetch even at age 0. Mutability is checked first, so `sealed` never rescues a `mutable_critical`
  table.
- **`verified` defaults to `True`.** DESIGN requires a nightly checksum only for `append_rarely`;
  defaulting to "no change seen" means the default is the design's baseline, and a `False` is always
  an explicit measurement.
- **Policy validation is loud**: unknown mutability string, `theta` outside `(0, 1]`, negative TTLs,
  an inverted range, and mixed aware/naive range endpoints all raise `ValueError` with the offending
  value. A typo in a per-table YAML override must not silently turn the cache off or on.
- **`Mutability` is a `Literal` in `freshness.py`, not a new models module.** No shared mutability
  enum exists yet (the classifier that produces one lives in the bootstrap lane, D9). Exporting the
  literal and `MUTABILITY_CLASSES` from `mdqm.cache` lets that lane import it instead of duplicating
  the four names.
