## Summary
Catalog parsers turn `pg_stats` / `pg_class`, Oracle `ALL_TAB_COL_STATISTICS`, a normalised SQL Server stats row, and Elasticsearch index stats into the same models. PostgreSQL collection tries the catalog first and falls back to a capped read. The default quiet window is 21:00-07:00 Asia/Jerusalem; a deployment's `quiet_windows` replaces it. `force` overrides the clock, not a disabled collector. Incremental collection skips a partition whose row and byte counts are unchanged. `find_data` and `POST /context` append one short stats line for a table the pack already named. The five-tool list is unchanged. `''` and `0` listed in a sentinel YAML file are compiled as `NULLIF`.
## Decisions
Sentinels are not a field of the semantic layer. Adding one would change the version hash of every layer. They live in a side file the compiler and the linter read. Oracle, SQL Server, and Elasticsearch parsers are tested on fixture rows. Only PostgreSQL has an executor, and only when the compose service is up.
## Deviations
Discovery of the `mdqm.adapters` entry-point group now treats a missing optional driver (no `oracledb` on a dev install) as unavailable rather than requiring every declared adapter to import. That matches the registry's existing warning. `mypy` 2.4 also required a cast on the Oracle adapter's raw driver exception when the `oracle` extra is not installed.
